# Candidate Screening Platform

A Hebrew-first, RTL web app that collects applicants for a technology role,
runs a 30-minute server-timed assessment, and gives the hiring manager one
fast admin screen to find who's worth an interview. Full design spec lives
in [`docs/`](docs/) — start with `docs/DESIGN_SUMMARY.md`.

This README covers **setup and deployment**. For "what's built vs. what's
left", see [`IMPLEMENTATION_STATE.md`](IMPLEMENTATION_STATE.md). For
implementation decisions made where the spec was ambiguous, see
[`IMPLEMENTATION_NOTES.md`](IMPLEMENTATION_NOTES.md).

## Stack

Next.js 15 (App Router, TypeScript) on Render, Supabase (Postgres + Auth +
Storage), Resend (email), Sentry (errors), UptimeRobot (uptime). One Render
web service, no workers, no cron, no Redis. Package manager is **pnpm**
(pinned via `packageManager` in `package.json`; run `corepack enable` once
if `pnpm` isn't on your machine).

## Local development

```bash
corepack enable                 # gets you the pinned pnpm version
pnpm install
cp .env.example .env            # fill in values — see comments in the file
supabase start                  # local Supabase stack (Docker) — optional but recommended
pnpm migrate                    # applies supabase/migrations/*.sql
pnpm dev                        # http://localhost:3000
```

Running against a personal (non-local) Supabase project instead of
`supabase start` works too — just point `.env` at it.

```bash
pnpm test           # Vitest (unit/integration)
pnpm test:e2e        # Playwright
pnpm lint            # ESLint, incl. the RTL logical-properties rule
pnpm typecheck       # tsc --noEmit
pnpm build           # production build
```

## Production setup, from zero (≈ 75 minutes)

This mirrors `docs/DEPLOYMENT.md` §8 exactly; that document is the
authoritative version if anything here drifts.

1. **Create the Supabase project.** supabase.com → New Project → plan
   **Pro** (required: no project pausing, daily backups), region
   **eu-central-1 (Frankfurt)**. Copy from Project Settings → API: the
   project URL, `anon` key, `service_role` key, JWT secret. Copy from
   Project Settings → Database: the pooler ("Transaction") connection
   string and the direct connection string.

2. **Run migrations.**
   ```bash
   cp .env.example .env   # fill in MIGRATION_DATABASE_URL (direct connection, project-owner)
   pnpm install
   pnpm migrate            # runs `supabase db push` against MIGRATION_DATABASE_URL
   pnpm db:set-app-password
   ```
   The last command sets a real random password for the `app_user` role
   (created by migration `0001`) and prints a `DATABASE_URL` — that's the
   value you'll paste into Render in step 7. `MIGRATION_DATABASE_URL` is
   the project-owner credential; keep it in your password manager and as a
   GitHub Actions secret for the `migrate` workflow. **It must never be set
   on Render.**

3. **Create the first admin.**
   ```bash
   pnpm admin:add --email manager@example.co.il --name "שם המנהל/ת"
   ```
   This inserts an `admin_users` row and sends a Supabase Auth invite
   email. The invited admin sets a password and **must enroll TOTP MFA**
   before reaching any data page — that's enforced by the app, not
   optional. Later admins are added from `/admin/settings` once that
   screen is built.

4. **Configure Supabase Auth** (dashboard → Authentication):
   - Email provider on, "Confirm email" on, "Secure email change" on.
   - Site URL = your production `APP_BASE_URL`; add
     `<APP_BASE_URL>/admin/auth/callback` as a redirect URL.
   - Paste the Hebrew templates from `supabase/auth-templates/*.html` into
     Invite / Magic Link / Reset Password.
   - **Disable public sign-ups** — admins are invite-only.
   - Password policy: minimum 12 characters.
   - Confirm the `cv` storage bucket exists (created by migration `0001`).

5. **Set up Resend** (email is required at launch, not optional — see
   `docs/ARCHITECTURE.md` §1). Verify your sending domain's DNS records,
   create an API key.

6. **Set up Sentry.** Create a free project, copy the DSN. Add an alert
   rule: "new issue → email the hiring manager's address."

7. **Deploy to Render.** New → Blueprint → point at this repo (uses
   `render.yaml`). Fill in the `sync: false` env vars in the Render
   dashboard (see the table in `docs/DEPLOYMENT.md` §3, or the comments in
   `.env.example`): `APP_BASE_URL`, `DATABASE_URL` (from step 2),
   `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY`,
   `SUPABASE_JWT_SECRET`, `PRIVACY_CONTACT_EMAIL`, `RESEND_API_KEY`,
   `EMAIL_FROM`, `SENTRY_DSN`, `ALERT_EMAIL`. `CANDIDATE_COOKIE_SECRET` is
   auto-generated by Render. First deploy runs; boot checks confirm env,
   migration version, Sentry, and email config, and refuse to start if any
   of them are wrong (deliberately — see `docs/ARCHITECTURE.md` §3).

8. **DNS.** Point your domain's CNAME at the Render hostname; Render
   issues the TLS certificate automatically.

9. **UptimeRobot.** HTTP(S) monitor on `https://<your-domain>/api/health`,
   5-minute interval, keyword `"status":"ok"`, alert to the hiring
   manager's address.

10. **Notifications.** Subscribe the hiring manager's address to Render's
    and Supabase's status pages. In Render, enable "deploy failed" and
    "service unhealthy" notifications.

11. **Smoke test.** Apply as a candidate end-to-end (including resuming
    from a private/incognito window via the resume code), log into
    `/admin`, view the result, download the CV, reject the test candidate
    (a closure email should arrive), delete the test candidate. Force the
    cleanup sweep to confirm the CV leaves storage immediately rather than
    waiting up to an hour: `pnpm sweep:now`.

12. **Backups.** Confirm daily backups are on (default on Supabase Pro);
    consider enabling PITR. **Do a restore drill before launch**: restore
    the latest backup into a throwaway Supabase project, point a local
    checkout at it, confirm the smoke-test candidate and CV are there,
    then delete the throwaway project. Time it and write the time down
    somewhere the next person will find it.

13. **Calendar reminder.** Put a yearly reminder on the hiring manager's
    calendar: "annual runtime/dependency bump — book half a day of
    developer time" (the one planned maintenance exception; see
    `docs/ARCHITECTURE.md` §8).

14. **GitHub repo settings** (one-time, not covered by any file in this
    repo): enable **Dependabot alerts** under Settings → Security →
    Code security (this is a repo setting, not something `dependabot.yml`
    can turn on by itself — `.github/dependabot.yml` only configures
    *version-update* PRs, which are deliberately disabled here).

## Releasing a change that includes a migration

Migrations are forward-only and follow an **expand/contract** rule enforced
by `pnpm check-migrations` in CI (see `docs/DEPLOYMENT.md` §5):

1. Add the new migration file under `supabase/migrations/`.
2. Run the `migrate` GitHub Actions workflow (manual, `workflow_dispatch`)
   or `pnpm migrate` from a developer machine against
   `MIGRATION_DATABASE_URL`.
3. Merge to `main` — Render auto-deploys. The app checks the DB's applied
   migration version against the version compiled into the build at boot;
   a mismatch makes `/api/health` return 503, which makes Render roll the
   deploy back automatically, so a missed migration step fails safe.
4. Only drop/rename/tighten a column in a **later** release, once the
   release that stopped using it is live, and mark the statement with a
   `-- contract: <release>` comment — otherwise CI fails the PR.

## Running the hourly maintenance sweep on demand

There's no cron job — the sweep (IP anonymization, retention pruning, CV
purge-queue drain, invariant checks) runs opportunistically inside
`/api/health`, at most once an hour, forever, because Render and
UptimeRobot ping that endpoint continuously. To force it immediately
(useful right after a deploy or during a smoke test):

```bash
pnpm sweep:now
```

## Repository layout

```
src/app/(candidate)/[locale]/...   candidate pages (he by default, RTL)
src/app/admin/...                  admin pages
src/app/api/...                    route handlers (health, assessment runner)
src/assessment/                    pure scoring/generation modules (no I/O)
src/db/                            Postgres access (withCandidate/withAdmin/withSystem) + Supabase client
src/i18n/                          next-intl config + messages
src/lib/                           env validation, crypto helpers
supabase/migrations/               schema + seed (Supabase CLI convention)
supabase/tests/database/           pgTAP tests
scripts/                           setup/ops scripts (admin:add, migrate helpers, sweep:now, ...)
tests/unit, tests/integration      Vitest
tests/e2e                          Playwright
```

Almost everything under `src/app` is currently a placeholder with a
